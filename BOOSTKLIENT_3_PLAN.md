# BOOSTKLIENT® 3.0 — план создания веб-приложения

## 1. Идея продукта

BOOSTKLIENT® 3.0 — экосистема Pinterest для бизнеса.

Цель продукта: провести пользователя от первого знакомства с Pinterest до максимально автоматизированного продвижения.

Путь пользователя:

**Обучение → Исследование → Стратегия → Создание контента → Планирование → Публикация → Аналитика → Улучшение → Масштабирование**

Ключевая идея:

> От первого знакомства с Pinterest — до полной автоматизации продвижения.

---

## 2. Что должен объединить BOOSTKLIENT®

В одном сервисе должны быть объединены функции, ради которых пользователь сейчас использует несколько решений:

- Pinterest
- Tailwind
- PinClicks
- Airtable
- Canva
- аналитические сервисы
- ручные таблицы
- ручной анализ конкурентов
- ручное построение стратегии

BOOSTKLIENT® должен не просто показывать данные, а отвечать на вопрос:

> Что делать дальше именно этому пользователю?

# 4. ИИ-стратег — центральный интерфейс BOOSTKLIENT®

ИИ-стратег — не обычный чат-бот.

Его задачи:

- понять бизнес пользователя;
- провести первичный опрос;
- автоматически проанализировать сайт и товары;
- определить нишу;
- исследовать Pinterest;
- найти ключевые слова;
- найти конкурентов;
- анализировать тренды и сезонность;
- построить стратегию;
- обсудить стратегию с пользователем;
- изменить стратегию по запросу;
- сформировать контент-план;
- управлять функциями BOOSTKLIENT®;
- объяснять результаты аналитики;
- предлагать следующие действия.

Первый ключевой сценарий:

**Новый пользователь → диалог → анализ бизнеса → исследование → стратегия → согласование → принятие стратегии → первый контент-план**

---

## 5. Принцип архитектуры ИИ

Не обучать отдельную языковую модель для каждого пользователя.

Использовать:

**одно ИИ-ядро + данные конкретного бизнеса + память + инструменты + аналитика**

Языковая модель должна быть заменяемой.

Возможные модели:

- OpenAI
- DeepSeek
- Hermes
- другие совместимые LLM

Бизнес-логика не должна зависеть от конкретной модели.

## 7. Память пользователя

Каждый ИИ-стратег работает с конкретным бизнесом пользователя.

Рекомендуемая структура:

**User → Workspace → Business → Pinterest Accounts**

У пользователя может быть:

- несколько бизнесов;
- несколько Pinterest-аккаунтов;
- несколько стратегий.

Типы памяти:

### Профильная память

Стабильные факты:

- ниша;
- сайт;
- рынок;
- язык;
- аудитория;
- товары;
- цели;
- ограничения.

### Рабочая память

Текущее состояние:

- действующая стратегия;
- активные кампании;
- текущие приоритеты;
- используемые доски;
- текущая интенсивность публикаций.

### История решений

Хранить не только решение, но и причину:

- почему увеличили тему;
- почему отключили ключ;
- почему изменили частоту;
- почему создали доску;
- почему изменили стратегию.

## 8. Хранение данных

Не использовать RAG для всего.

### Обычная база данных

Для структурированных данных:

- аккаунты;
- товары;
- URL;
- ключи;
- позиции;
- доски;
- пины;
- даты;
- расписание;
- статусы;
- аналитика;
- настройки.

Предварительно: PostgreSQL.

### RAG (поиск по базе знаний перед ответом)

Использовать для знаний:

- правила Pinterest;
- обучающие материалы;
- методики построения стратегии;
- правила выбора досок;
- SEO-подходы;
- работа с трендами;
- внутренние исследования;
- продуктовые инструкции;
- накопленные лучшие практики.

# 9. Профиль бизнеса

ИИ должен выяснить или определить:

- что за бизнес;
- нишу;
- поднишу;
- сайт;
- магазин или маркетплейс;
- товары;
- категории;
- страну;
- язык;
- целевую аудиторию;
- цель продвижения;
- Pinterest-аккаунты;
- наличие готового контента;
- желаемую интенсивность продвижения.

Главный принцип:

> Не спрашивать то, что можно определить автоматически.

Например после анализа сайта:

> Я определил вашу нишу как «женская одежда». Основные категории: платья, костюмы, верхняя одежда. Всё верно?

# 10. Research Engine (модуль исследования)

Должен собирать:

## Ключевые слова

- основные запросы;
- связанные запросы;
- длинные запросы;
- поисковый спрос;
- динамику;
- сезонность;
- коммерческий интерес;
- конкурентность;
- релевантность бизнесу.

## Тренды

- растущие темы;
- падающие темы;
- начало сезонного спроса;
- темы, которые нужно готовить заранее.

## Конкуренты

- сильные аккаунты;
- лучшие доски;
- популярные пины;
- темы;
- ключевые слова;
- новые публикации;
- растущий контент.

## Gap Analysis (анализ пробелов)

Сравнивать пользователя с конкурентами:

> Конкуренты получают трафик по запросам, по которым у пользователя нет контента.

---

# 11. Strategy Engine (модуль стратегии)

Получает:

**профиль бизнеса + исследование + тренды + конкуренты**

Формирует:

- цель;
- основные направления продвижения;
- группы ключевых слов;
- рекомендуемые доски;
- контентные темы;
- частоту публикаций;
- сезонные кампании;
- план на 30 / 60 / 90 дней.

Стратегия должна быть редактируемой через диалог.

Пример:

> Не продвигай свадебные товары.

ИИ пересчитывает стратегию.

---

# 12. Content Engine (модуль контента)

Создаёт:

- идеи пинов;
- изображения;
- видео;
- заголовки;
- описания;
- ключевые слова;
- теги;
- хештеги;
- alt text (альтернативный текст);
- несколько вариантов одного товара или URL.

Каждый пин должен быть связан с причиной его создания:

**товар / URL → ключ → поисковое намерение → доска → цель → стратегия**

---

# 13. Новый принцип генерации BOOSTKLIENT® 3.0

В версии 2.0 большой объём пинов генерируется сразу.

В BOOSTKLIENT® 3.0 перейти на потоковую модель.

Не создавать заранее весь объём, например 110 пинов.

Использовать:

## Start Batch (стартовый пакет)

При запуске стратегии создать ограниченный запас готовых пинов.

Например:

- 20–30 пинов;
- провести проверки;
- отправить пользователю на одобрение;
- после одобрения поставить в очередь.

## Rolling Buffer (скользящий запас)

Пока одобренные пины публикуются, следующие создаются в фоне.

Система постоянно поддерживает установленный запас готового и одобренного контента.

Пример:

- публикация: 20 пинов в сутки;
- целевой запас: 40 одобренных;
- при снижении ниже заданного порога запускается новая генерация.

---

# 14. Жизненный цикл пина

Рекомендуемые статусы:

1. **IDEA** — идея
2. **GENERATING** — генерируется
3. **VALIDATING** — автоматические проверки
4. **WAITING_APPROVAL** — ждёт одобрения пользователя
5. **APPROVED** — одобрен
6. **QUEUED** — находится в очереди
7. **PUBLISHING** — отправляется
8. **PUBLISHED** — опубликован
9. **REJECTED** — отклонён
10. **REWORK** — требуется переделка
11. **FAILED** — ошибка

Неодобренный пин по умолчанию не публикуется.

---

# 15. Контроль качества

Не делать тяжёлые ИИ-проверки непосредственно перед публикацией.

Разделить на два этапа.

## Heavy Validation (тяжёлая проверка)

Выполняется заранее и в фоне:

- качество текста;
- соответствие товару;
- соответствие ключу;
- соответствие доске;
- качество изображения;
- проверка дублей;
- проверка слишком похожего контента;
- соответствие стратегии;
- запрещённые элементы;
- корректность URL.

## Pre-Publish Check (быстрая проверка перед публикацией)

Только техническая проверка:

- URL доступен;
- аккаунт подключён;
- доска существует;
- файл доступен;
- пин ещё не опубликован;
- разрешение пользователя не отозвано.

---

# 16. Уникальность и разнообразие

Нельзя обещать математическую 100% уникальность.

Нужно снижать вероятность повторов технически.

Использовать:

- историю заголовков;
- историю описаний;
- историю изображений;
- историю ключей;
- embeddings (векторное представление смысла);
- visual embeddings (векторное сравнение изображений);
- пороги сходства.

Если новый вариант слишком похож на старый:

**не принимать → сгенерировать новый вариант.**

---

# 17. Approval Queue (очередь на одобрение)

Контроль пользователя обязателен.

Очередь хранится внутри BOOSTKLIENT®, но не обязательно заставлять пользователя ежедневно заходить в веб-приложение.

Предусмотреть внешние каналы одобрения:

- Telegram;
- MAX;
- позднее Email / Push.

---

# 18. Telegram / MAX как канал одобрения

Пользователь подключает Telegram или MAX.

Раз в сутки получает подборку пинов для проверки.

Вариант ежедневного сообщения:

> На завтра подготовлено 24 пина.
>
> 18 прошли проверку с высоким рейтингом.
>
> 6 требуют дополнительного внимания.

Действия:

- посмотреть пины;
- одобрить;
- отклонить;
- переделать;
- одобрить выбранные;
- одобрить пакет.

Все реальные статусы при этом хранятся только в BOOSTKLIENT®.

Telegram / MAX — интерфейс управления, а не источник данных.

---

# 19. Режимы контроля

Предусмотреть минимум три режима.

## Строгий

Каждый пин требует ручного одобрения.

## Умный

Надёжные пины можно одобрять пакетно, спорные показываются отдельно.

## Автопилот

По явному разрешению пользователя система может автоматически пропускать пины, которые удовлетворяют установленным критериям качества.

Автопубликация без пользовательского разрешения не включается.

---

- время;
- доску;
- URL;
- ключ;
- тематику;
- интервал;

# 21. Analytics Engine (модуль аналитики)

Собирать:

- показы;
- сохранения;
- переходы;
- позиции;
- лучшие пины;
- лучшие ключи;
- лучшие доски;
- лучшие товары;
- трафик;
- конверсии;
- продажи, если доступны.

Главный принцип:

> Не просто показать цифры, а объяснить, что произошло и что делать дальше.

---

# 22. Recommendation Engine (модуль рекомендаций)

Примеры:

- найден новый растущий запрос;
- этот товар получает больше переходов;
- эта доска просела;
- создать ещё варианты успешного пина;
- скоро начинается сезон;
- у конкурентов появилась новая сильная тема.

---

# 23. Learning Loop (цикл самообучения)

Система постоянно сравнивает:

**что сделали → какой получили результат**

И предлагает или выполняет корректировки:

- ключевых слов;
- тем;
- досок;
- частоты;
- визуалов;
- заголовков;
- контент-плана;
- стратегии.

Цикл:

**Research → Strategy → Create → Validate → Approve → Publish → Analyze → Learn → Adjust → Repeat**

# 24. Быстродействие

Не использовать мощную модель для каждой операции.

Разделять задачи.

## Простые

Пример:

> Сколько пинов опубликовано сегодня?

Обычный запрос к базе данных.

## Средние

Пример:

> Какие ключи выросли?

Аналитика + быстрая модель при необходимости.

## Сложные

Пример:

> Перестрой стратегию на следующие 3 месяца.

Использовать более сильную модель и глубокий анализ.

Предусмотреть Model Router (маршрутизатор моделей).
