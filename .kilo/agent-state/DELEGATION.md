# Делегирование для экономии лимита Codex

## Роли

- **Claude Code — руководитель с 6 октября 2026.** Оценивает каждую задачу, определяет её границы, выбирает исполнителя, выдаёт поручение, принимает результат и отвечает владельцу.
- **OpenCode — исполнитель ограниченных задач с бесплатной моделью через OpenRouter.** Выполняет поиск, сбор фактов, черновики и механические правки в согласованных файлах, возвращает краткий отчёт с доказательствами. Запускается через `.kilo/agent-state/run_opencode.py`; результат принят только после проверки Claude.
- **Codex — генерация изображений (основная ниша) и отдельные поручения Claude или владельца.** Код и тексты по умолчанию не берёт, чтобы беречь недельный лимит. Без поручения не коммитит и не занимает файлы. Прямую задачу владельца выполняет, а коммит и занятые файлы согласует с Claude через `LOG.md`.
- OpenRouter — провайдер моделей, OpenCode — агент, который может использовать эти модели. Они не взаимозаменяемы. Прямые вызовы OpenRouter API и поручение агенту OpenCode — разные способы работы.
- Владелец подтвердил: поручения выполняет OpenCode, связь только через файлы в `.kilo/agent-state/`. HTTP-API OpenCode и прямые вызовы OpenRouter API для этой схемы не использовать.

## Полномочия Claude Code

Владелец поручил Claude принимать все решения по выполнению поставленной задачи после проверки фактов и результатов. OpenCode предлагает варианты и выполняет поручения; его выводы становятся основанием для действий только после приёмки Claude. В пределах согласованной задачи руководитель самостоятельно выбирает способ реализации, распределение работы, доработки и принимает либо отклоняет результат. Обычные технические решения не возвращать владельцу на согласование. Если требуется выйти за пределы задачи или ранее разрешённых расходов и действий, уточнить только недостающее разрешение.

Если Claude недоступен, Codex или OpenCode сами принимают обычные технические решения и безопасные локальные изменения, записывая в `LOG.md`: `<агент>: <решение>; причина: Claude недоступен; жду приёмки`. Результат ожидает приёмки Claude. Решения владельца — модель, `.env`, настройки, база данных, удаление чужих изменений, расходы и правка правил — не заменяются.

## Решение перед каждой задачей

1. Прочитать `LOG.md`, `HANDOFF.md` и реестр `agent.sh list`.
2. Оценить сложность, объём работы, цену ошибки и затраты на передачу контекста и приёмку.
3. По умолчанию поручать исполнителю ограниченные работы: поиск по заданной области, сбор фактов, документацию, локальные исправления с ясными требованиями, запрошенные проверки.
4. Руководитель оставляет себе постановку задачи, архитектурные решения, неоднозначную диагностику, разрешение конфликтов и итоговую приёмку. Однострочную правку дешевле сделать самому, если поручение и проверка потребуют больше работы.
5. Коротко сообщить решение: что делегируется, кому и что проверит Claude. Не обещать экономию в процентах без измерений.

## Как выдать поручение

Создать `TASK-<id>.md` в этой папке после `claim`. Записать в `LOG.md` имя исполнителя и путь поручения через `agent.sh note claude "..."`.

Обязательные поля поручения:

```text
ID / статус: предложено | принято | выполняется | готово | доработка | заблокировано | принято Claude
Исполнитель / модель: фактический идентификатор либо пока не выбран
Цель: наблюдаемый результат
Контекст: только нужные факты, пути и решения
Разрешённые файлы: точные пути или ограниченная область поиска
Ограничения: что нельзя менять, внешние вызовы и бюджет
Критерии приёмки: конкретные признаки готовности
Проверки: только необходимые и разрешённые владельцем
Результат: путь RESULT-<id>.md
```

Исполнитель подтверждает принятие в `LOG.md`, занимает файлы своим именем до правки и обновляет статус. Запись поручения не означает, что агент запущен. Без подтверждения задача остаётся предложенной; руководитель не сообщает о выполнении или фоновой работе.

## Экономия

### Запуск исполнения

Руководитель сам запускает подготовленное поручение: `python3 .kilo/agent-state/run_opencode.py run TASK-004 --model openrouter/openrouter/free --timeout 240`. Это официальный CLI без подключения к HTTP-серверу. Поручение передаётся файлом, фактический ответ сохраняется в RESULT-файл. Для анализа укажите разрешённые пути в JSON-блоке `runner` поручения. Текущий запускатель разрешает только чтение этих файлов; для правок требуется отдельное согласованное расширение прав.

Проверка выполнения: `python3 .kilo/agent-state/run_opencode.py status TASK-004`. Статусы: starting, running, awaiting_review, failed, timed_out_or_interrupted. Блокировка предотвращает второй параллельный CLI-процесс; уже запускавшийся ID не запускается повторно автоматически. Новый запуск после ошибки — только новое поручение по решению руководителя. Тайм-аут останавливает процесс. Это запуск по команде руководителя, не постоянно работающий демон. За результатом и приёмкой следит Claude во время активной работы.

- Передавать короткое поручение и ссылки на точные файлы, а не весь диалог или репозиторий.
- Не повторять работу исполнителя: руководитель смотрит изменённый участок, результат и существенные доказательства.
- Объединять близкие мелкие задания, если у них одни требования и область файлов.
- Начинать с самой экономичной доступной модели, пригодность которой подтверждена для этого вида работы. Бесплатный каталог не доказывает качество или возможность успешного вызова.
- Не переключать модель Codex и не выбирать платную модель исполнителя без нужного разрешения. Ранее выданное разрешение учитывать в его пределах; разрешение на GigaChat не переносить автоматически на OpenRouter.
- Не запускать бесконечные попытки. После неудачи определить причину; одна адресная доработка, затем руководитель пересматривает способ выполнения. При тайм-ауте платный запрос автоматически не повторять.
- Секреты, `.env`, ключи и пароли не передавать в поручениях или отчётах.

## Приёмка

Исполнитель возвращает в `RESULT-<id>.md`: результат, изменённые пути, выполненные проверки с фактическим исходом, оставшиеся проблемы, модель и доступные показатели расхода.

Claude проверяет соответствие запросу, существенный diff, отсутствие чужих изменений и доказательства проверок. При необходимости запрашивает адресную доработку. Непроверенное явно обозначает. Ответ исполнителя не считается автоматически верным.

В `LOG.md` фиксировать итог каждой делегированной задачи: ID, вид работы, исполнитель/модель, принято или доработка, число попыток, известные токены/стоимость, объём приёмки Claude. Если расход неизвестен, писать «неизвестен», а не вычислять его из длины ответа. При следующих задачах использовать результаты этого журнала для выбора исполнителя.

## Общий репозиторий

- В командах задавать `export AGENT_NAME=claude` для руководителя или имя исполнителя (`codex`, `opencode`). Не менять общий `git config agent.name`.
- Перед правкой использовать `agent.sh claim`; при конфликте не трогать чужие файлы.
- Перед каждой новой задачей и при получении результата перечитать `LOG.md`.
- Коммиты и публикация — только в рамках разрешения владельца. Не коммитить в `main`, не использовать `git add -A`, не обходить хук.
- После завершения работы обновить `HANDOFF.md` и освободить файлы. Если предстоит согласованный коммит, держать их занятыми до коммита.

Проверка 3 октября 2026: Zen big-pickle через CLI вернул 403 FreeTierError; прошлые успешные сообщения не гарантируют доступность нового запуска. OpenRouter Free через тот же CLI дал фактический ответ. Права read задаются относительно корня проекта, согласно реализации установленной версии.


## Ограничения, проверенные расширенным прогоном

- На каждую отдельную задачу сначала выделять конкретную работу OpenCode. Пустой ответ, сообщение об успехе CLI или HTTP200 не считаются результатом.
- Запускатель ограничивает agent.plan.steps=3 через процессный OPENCODE_CONFIG_CONTENT (поддержка подтверждена debug config установленного CLI); постоянные настройки не меняются. Для простой задачи передавать один краткий контекст, не полный репозиторий.
- openrouter/openrouter/free дал два пустых результата на крупных поручениях; NVIDIA lightning не завершился за180с, Google Gemma вернул403 Blocked by Google AI Studio. Не назначать эти маршруты повторно без установленной причины восстановления.
- cohere/north-mini-code:free реально ответил на TASK-010/011/012. Пригодность показана лишь для простых ограниченных критериев. Семантическую оценку ответов нельзя автоматически принимать: TASK-011 пропустил выдуманный источник, TASK-012 предлагал отклонить валидный вход.
- Полезные части принять после проверки, неверные отклонить. При блокировке исполнителя руководитель продолжает необходимые проверки; не тратит время на бесконечный перебор бесплатных моделей. Измерять расход и успех по семействам задач; бесплатная стоимость токенов не равна доказанной экономии подписки Codex.

## Проверка семантического критика — TASK-016

Маршрут cohere/north-mini-code:free не использовать для семантической приёмки: после частичных/ошибочных011/013/015, TASK016 утверждал ложный total для неполного списка. Усложнение инструкций не доказало пригодность. Не повторять такие задания этому маршруту; оставить узкие механические работы с проверяемым результатом. Руководитель отвечает за итоговую оценку. Cost0 не доказывает экономию подписки.
