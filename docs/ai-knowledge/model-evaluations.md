# Выбор моделей для задач ИИ-стратега

Этот журнал хранит результаты сравнений моделей и статистику по семействам задач. Тестовые вызовы не считаются рабочими обращениями пользователей. Сценарии оценки хранятся в `examples/` и не индексируются в RAG.

## Реестр задач

| Семейство задач | Рабочий объём | Выбранная модель | Статус оценки |
| --- | --- | --- | --- |
| Текстовый диалог Стратега | Не измеряется по типу задачи | `GigaChat-2-Pro` | Сравнены текстовые ответы по 24 сценариям |
| Диалог с вызовом Pinterest или Wildberries | Не измеряется по типу задачи | Общий маршрутизатор, сначала `GigaChat-2-Pro` | Отдельный сравнительный прогон инструментов ещё не проводился |
| Поиск по утверждённым документам RAG | Не измеряется по типу задачи | `EmbeddingsGigaR` локально, NVIDIA резерв | Сравнены три бесплатных маршрута; основной GigaChat проверен после активации пакета |

Рабочий объём нельзя вывести из числа тестовых сценариев. Когда появится учёт типа задачи в рабочих запросах, сюда следует добавлять период и фактическое число запросов без текстов пользователей.

Ожидаемые ответы моделям не передавались. Для сценариев с источником передавались фрагменты утверждённых локальных материалов. Лимит ответа — 1200 токенов.

## 2 октября 2026: ручная проверка через интерфейс после исправления маршрута

Пользователь повторил 4 вопроса в одной сессии чата. Ошибочный ответ со списком подключённых профилей больше не появился. Ручная оценка: 1 ответ прошёл, 2 частично прошли, 1 провалился. Это выборка из проверочного набора, а не статистика рабочих запросов. Фактическая модель, токены, задержка и применённые RAG-фрагменты для этих четырёх ответов не зафиксированы; результат нельзя приписать одной модели.

- Частично: ответ о ежедневной частоте публикаций без ссылки категорично утверждает отсутствие официальной нормы и приписывает Pinterest рекомендацию о регулярности.
- Прошёл: ответ о 12 исходящих кликах прямо говорит, что по ним нельзя узнать количество заказов.
- Частично: ответ о росте переходов и заказах не выдумывает числа, но не говорит прямо, что причина роста неизвестна без статистики.
- Провал: ответ о Правилах сообщества объявляет любую публикацию «связанного с» перечисленными темами запрещённой, не различая контекст, удаление и ограничение распространения; ссылка на официальный источник не дана.

После оценки уточнены правила ответа для неподтверждённых отрицательных утверждений и вопросов о причинах метрик. Вопросы о Правилах сообщества теперь получают действующий утверждённый локальный источник и ссылку; для них не запускается поиск по эмбеддингам. Следующий шаг — повторить спорные вопросы с фиксацией модели и источников. Платных вызовов в рамках этой записи не выполнялось.

Позднее логи пяти отдельных ручных сессий показали сбой получения эмбеддингов (`GigaChatProviderError`) при успешных ответах чата через локальный запасной поиск. Два коротких диагностических запроса к `EmbeddingsGigaR` также завершились ошибкой; второй раскрыл HTTP `402`. По документации GigaChat это означает исчерпание доступных токенов запрошенной модели. Расход этих неуспешных вызовов не установлен. До восстановления квоты результаты ручной проверки не следует считать проверкой обычного пути RAG.

Добавлен локальный поиск по утверждённым фрагментам базы знаний с передачей ссылок на источники. После HTTP `402` повторные вызовы эмбеддингов блокируются на 5 минут, а чат использует локальный поиск. Обычный семантический поиск возобновится после восстановления квоты; качество нового запасного пути в ручном диалоге ещё не проверено. Дополнительных платных запросов при этом изменении не делали.

После добавления точного ответа из утверждённого источника прогон `1bcc8872ee` дал два верных ответа с официальной ссылкой, 0 токенов GigaChat. Это подтверждает данный узкий сценарий, а не все возможные вопросы о правовом режиме данных API. Прошли 39 тестов `apps.strategist.tests` и `apps.knowledge.tests`.

### Критик ответов до показа пользователю

Добавлен отдельный вызов GigaChat-критика после генерации текста. Критик получает вопрос, ограниченную историю, бизнес-профиль, найденные материалы и ответы инструментов. Он возвращает `pass` или `revise`; для `revise` предлагает исправленный текст. Перед показом применяется локальная проверка явного требования «один шаг» и существующие ограничения совета. Некорректный ответ критика или ошибка его API закрывают ответ заглушкой. Прямые ответы из базы и API не отправляются на эту платную проверку. В `AIMessage.assets.critic` сохраняются статус, модель и учтённые токены без текста переписки.

На пяти синтетических парах «вопрос — черновик» `GigaChat-3-Pro` верно отклонил четыре ошибочных ответа (заказы из кликов, несколько первых шагов, выдуманный запрет CTA, слоган вместо CTA) и пропустил один корректный. `GigaChat-2-Pro` пропустил конкретный слабый CTA; `GigaChat-2-Max` также пропустил его; `GigaChat-3-Ultra` отклонил, но на всём наборе не сравнивался. Поэтому для критика пока выбран `GigaChat-3-Pro`, генератор остаётся на обычном маршруте. Выбор предварительный: одна формулировка на случай не доказывает стабильность модели. Денежная стоимость, медиана/p95 задержки и рабочая частота задач не измерены.

Промежуточные живые прогоны выявили ложные одобрения и блокировки: GigaChat-критик путал «первый Pin» с «первым шагом», а повторная проверка собственного исправления иногда давала пользователю заглушку. Схема сокращена до одного вызова критика на ответ; его исправление используется после локальной проверки, при плохом исправлении допускается одна перепись генератором. Отдельные прогоны `67c646c257` (визуал + CTA, 2053 токена, из них 1036 критик) и `ab888646f7` (один шаг, 1934 токена, из них 856 критик) дали короткие исправленные ответы без блокировки. Прогон `0f8f57b607` не зачтён: бесплатный симулятор остановился до первого ответа.

Общий прогон `f9cfcb67d8`: 9 диалогов, 15 ответов, 6784 учтённых токена GigaChat. Критик проверил 4 ответа модели: 3 одобрил, 1 исправил; на проверку ушло 3027 токенов. Остальные 11 ответов пришли из прямых маршрутов без критика. Вручную проверены первые ответы: критических выдуманных чисел и блокировок нет, но симулятор по сценарию подписи сначала спросил о стиле вместо подписи. После уточнения сценария прогон `34fcbd2a58` дал короткую подпись на правильный первый вопрос (1912 токенов всего, 966 у критика). Обнаружен и отдельный предел критика: на сохранённой фразе «каждый элемент неповторим» он не заметил неподтверждённое обещание уникальности. Это остаётся открытым дефектом; общий прогон не доказывает точность всех фактов и не измеряет качество на рабочих чатах.

## Решение: LLM-критик удалён

Критик удалён из кода полностью, без флага: `apps/strategist/critic.py`, вызов после генерации, `GIGACHAT_CRITIC_MODEL`, `AIMessage.assets.critic` и агрегация в `run_strategist_arksim.py`. Основания не в качестве конкретных прогонов, а в накопленной статистике журнала.

Цена. Критик съедал около половины бюджета токенов: 3027 из 6784 в `f9cfcb67d8`, 1036 из 2053 в `67c646c257`, 856 из 1934 в `ab888646f7`. Проверялась только часть ответов — 4 из 15 в общем прогоне, — но стоимость платилась на каждом ответе, доходившем до генератора.

Эффект был отрицательным, а не нейтральным. Схема была fail-closed: `blocked` и `unavailable` закрывали готовый ответ заглушкой «Не удалось надёжно проверить ответ», то есть платная ошибка второго вызова уничтожала полезный результат первого. Одновременно критик давал ложные одобрения — путал «первый Pin» с «первым шагом» — и не увидел неподтверждённое обещание уникальности, то есть даже в тех случаях, когда срабатывал, не находил дефект надёжно.

Что осталось вместо него — только проверяемое. Детерминированные маршруты `grounded_answers.py` (короткий ответ на «вчера/заказы» без аккаунта и чисел), `enforce_advice_boundaries`, обязательные антиспам- и community-правила в системном промпте. Они не могут «одобрить» ерунду и не могут заблокировать пользователя из-за ошибки провайдера. Чего они не делают: не читают смысл ответа. Это осознанный размен качества на предсказуемость и стоимость.

Указание про один первый шаг удалено из системного промпта и из политики ответа — предыдущее решение оставить пересмотрено, по прямому требованию владельца.

Замер до и после на GigaChat-2-Pro, мастерская керамики, два запроса, реальные вызовы. Слева снято, справа добавлено.

| Запрос | С указанием | Без указания |
|---|---|---|
| «Окей, но с чего начать конкретно? Один первый шаг.» | одно действие | одно действие — просьба выполнена |
| «Я сегодня создал аккаунт Pinterest. Досок и стратегии пока нет. С чего начать?» | три шага в прозе, без нумерации | пять шагов нумерованным списком |

Выводы. Прямая просьба пользователя выполняется и без системного указания: это факт о том, что модель отвечает на запрос, а не на правило, и он делает указание избыточным. Главное возражение против удаления — «указание якобы держало ответ на один шаг» — не подтвердилось: до удаления на открытом вопросе модель всё равно выдала три шага, то есть правило и до этого не работало. Разница наблюдаема только в открытом вопросе и сводится к более списочной подаче.

Стоимость замера: 1878 токенов до и 741 после, две пары вызовов GigaChat-2-Pro. ArkSim для замера не использовался: `arksim==0.3.8` закреплён в `requirements/eval.txt` как инструмент одноразового окружения, но в образ приложения не устанавливается, поэтому в контейнере его нет. Ставить библиотеку в рабочее окружение без отдельного решения владельца не следовало. Поэтому замер ограничен двумя сценариями без имитации уточнений пользователя — это не полноценная оценка качества, а проверка одного спорного указания.

Побочный эффект, который стоит иметь в виду: нумерованный список из пяти пунктов на открытый вопрос слабее согласуется с правилом «для обычного вопроса достаточно 2–5 предложений» в политике ответа. Это отдельная настройка формулировки, а не повод возвращать правило, которое не удерживало поведение.
