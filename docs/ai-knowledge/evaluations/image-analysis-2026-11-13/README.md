Ветка: `feature/pins-from-images`. Основной контекст: [.kilo/agent-state/HANDOFF.md](../../../../.kilo/agent-state/HANDOFF.md) и [план разработки](../../../../BOOSTKLIENT_3_IMAGE_STRATEGIST_PLAN.md).

## Главное решение владельца

Качественный автоматический отбор **ещё не принят**. Предыдущие заявления о готовности были преждевременными: исправление отдельных примеров и зелёные тесты обработки ответов не доказывают точность распознавания фотографий. Две проверки одной модели могут ошибаться одинаково.

Обязательный следующий порядок:

1. Заранее зафиксировать ожидаемые оценки на отдельном наборе хороших и неподходящих изображений. Разделить подтверждённую владельцем разметку, предварительную редакционную оценку и спорные случаи.
2. Сравнить варианты анализа на одинаковых данных, сохраняя версии запросов, правил и исходные ответы.
3. Проверить выбранный вариант на новых фото, которые не участвовали в настройке. Отдельно считать ошибочные одобрения, ошибочные отказы и передачу человеку.

Не называть набор независимой финальной проверкой после того, как его использовали для изменения запроса или правил. Не объявлять модуль готовым по одному успешному прогону.

## Что сделано

Общий `review_image()` используется загрузкой фото и evaluator. Первый этап оценивает изображение, второй проверяет кандидата по наблюдаемым признакам. Для брюк отдельно проверяются компоновка, нижняя видимая часть человека, пояс и полнота изделия. Непустое описание обязательно в первой оценке и во всех ветках второй проверки, включая коллажи, наборы, костюмы и до/после. Пустой ответ не дополняется выдуманным текстом и не превращается в готовую положительную оценку.

Текущие версии:

- модель: `GigaChat-2-Pro`;
- запрос: `image-review-v14-required-observation`;
- правила: `owner-rules-2026-11-13-v10-required-observation`.

Правила владельца: размерные таблицы, отдельные фрагменты товара и коллажи отклонять; понятное до/после допускается как дополнительный пин. Разногласие проверок о целостности одиночного товарного кадра — «Допустим», нужна ручная проверка.

Последний полный Django-прогон: **514 тестов OK**, 83,864 с. Целевые проверки: 61 тест OK. `check`, `makemigrations --check --dry-run`, `migrate --check`, `git diff --check` успешны. Это проверка поведения кода, не доказательство качества модели.

## Что сохранено в Git

- `runs/` — снимок всех сохранённых image-eval результатов, исходных ответов, запросов, промежуточных экспериментов, отчётов, фотографий, диагностических runner-скриптов и логов проверок. Снимок хранит историю, включая неудачные варианты.
- `image-analysis-test-fixtures.tar.gz` — все тестовые изображения, инвентари и публичные данные карточек из Docker MEDIA_ROOT: 184 файла, 11 карточек.
- `source-datasets.tar.gz` — исходные CSV разметки в точных байтах до возможной нормализации переводов строк при публикации.
- `MANIFEST.json` — размеры и SHA-256 файлов пакета для проверки переноса.

Секреты, локальный `.env`, виртуальное окружение и реальные бизнес-данные в пакет не входят.

## Восстановление на рабочем компьютере

Получить ветку `feature/pins-from-images`, настроить собственный локальный `.env` и запустить проект через Docker Compose. Команды ниже выполняются из корня репозитория.

Сначала проверить перенос пакета без API-вызовов:

```bash
python3 - <<'PY'
import hashlib, json
from pathlib import Path
root = Path('docs/ai-knowledge/evaluations/image-analysis-2026-11-13')
manifest = json.loads((root / 'MANIFEST.json').read_text())
for item in manifest['files']:
    path = root / item['path']
    assert path.stat().st_size == item['bytes'], path
    assert hashlib.sha256(path.read_bytes()).hexdigest() == item['sha256'], path
print('Пакет проверен:', len(manifest['files']), 'файлов')
PY
```

Восстановить сохранённые отчёты в прежний ignored-каталог. Команда предназначена для новой рабочей копии; при уже существующих результатах сначала сравнить их, чтобы не перезаписать чужую работу.

```bash
mkdir -p var/strategist-eval
cp -a docs/ai-knowledge/evaluations/image-analysis-2026-11-13/runs var/strategist-eval/image-analysis
docker compose up -d
docker compose cp docs/ai-knowledge/evaluations/image-analysis-2026-11-13/image-analysis-test-fixtures.tar.gz web:/tmp/image-analysis-test-fixtures.tar.gz
docker compose exec -T web python - <<'PY'
import os, tarfile
os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'config.settings.development')
import django
django.setup()
from django.conf import settings
with tarfile.open('/tmp/image-analysis-test-fixtures.tar.gz') as archive:
    archive.extractall(settings.MEDIA_ROOT, filter='data')
print('Тестовые изображения восстановлены')
PY
```

После восстановления можно проверить dataset без GigaChat:

```bash
docker compose exec -T web python scripts/evaluate_image_analysis.py --dry-run --dataset docs/ai-knowledge/examples/image-review-confirmed-2026-11-12.csv --output var/strategist-eval/image-analysis/work-computer-dry-run.json
```

Живые вызовы в этих командах не выполняются. Сохранённые диагностические runner-скрипты используют фиксированные имена старых прогонов и отказываются перезаписывать их; не запускать их как универсальные команды нового измерения.
