# ИИ-стратег: корпус знаний и примеры

Статус: начальный курируемый набор подключён к RAG ИИ-стратега. Он включает семь утверждённых русскоязычных документов Pinterest и BOOSTKLIENT®.

Индексатор читает только `knowledge/*.md` со статусом `approved` и областью `global`. Планы, черновики, UI-правила и evaluation-примеры в базу знаний не попадают.

## Текущая реализация

- `apps/knowledge/` загружает утверждённые Markdown-документы, делит их по заголовкам и смысловым границам с перекрытием соседних фрагментов, создаёт embeddings и сохраняет векторы и метаданные в PostgreSQL.
- Провайдер эмбеддингов задаётся `KNOWLEDGE_EMBEDDING_PROVIDER` (`gigachat` или `openrouter`), модель — `KNOWLEDGE_EMBEDDING_MODEL`. Локально основной поиск использует `EmbeddingsGigaR`; при ошибке GigaChat резервный поиск использует `nvidia/llama-nemotron-embed-vl-1b-v2:free` через OpenRouter. Ответы чата создаёт GigaChat. Для резервного поиска хранятся отдельные векторы тех же утверждённых фрагментов.
- Для OpenRouter нужен `OPENROUTER_API_KEY`. Локальный Compose передаёт хостовый `HTTPS_PROXY` только адаптеру OpenRouter через `OPENROUTER_PROXY_URL`; остальные API используют прежние сетевые настройки.
- `python manage.py index_knowledge` выполняет dry run без API и записи. `python manage.py index_knowledge --embed` вызывает выбранный API; без флага команда не расходует токены. При смене модели индекс пересчитывается даже для неизменённых документов.
- При запросе чата найденные фрагменты и их официальные ссылки добавляются в системный контекст. При ошибке основного API поиск обращается к резервному NVIDIA, если задан `KNOWLEDGE_FALLBACK_EMBEDDING_MODEL` и резервные векторы доступны. Если семантический поиск не дал результатов, используется локальное ранжирование утверждённых фрагментов.
- Списки источников не индексируются как смысловые фрагменты: ссылки сохраняются в метаданных и выдаются вместе с найденным знанием.

Текущий локальный индекс: 7 документов, 30 фрагментов с GigaChat-векторами и 30 резервными NVIDIA-векторами. Новые или изменённые документы надо индексировать командой `index_knowledge --embed`; неизменённые документы с теми же моделями пропускаются по контрольной сумме.

Бесплатный NVIDIA endpoint заявлен как пробный и регистрирует входные запросы. При его срабатывании вопрос пользователя передаётся OpenRouter. Локальный выбор не меняет производственную конфигурацию по умолчанию; в продакшене резерв включается только при явной настройке и после проверки условий обработки бизнес-данных.

## Назначение файлов

- `knowledge/` — утверждённые справочные знания продукта; после проверки источника их можно индексировать.
- `policy/` — обязательные правила ответа. Их применяет системный prompt и backend; они не должны зависеть от того, нашёл ли их RAG.
- `examples/` — примеры диалогов для оценки и регрессионных тестов. Не индексировать как обычные знания: иначе пример может быть извлечён как реальный факт.
- `model-evaluations.md` — решения по моделям, статистика сравнений и ограничения проверок; не индексировать в RAG.
- `sources/` — реестр первоисточников и их ограничений.

| `knowledge/boostklient-product-scope.md` | RAG, global | Сводка стабильного назначения продукта из `PRODUCT.md` |
| `knowledge/pinterest-business-basics.md` | RAG, global; перепроверять изменяемые ограничения | Краткая выжимка публичной справки Pinterest Business со ссылками и датой проверки |
| `knowledge/pinterest-spam-prevention.md` | RAG, global; обязательный источник preflight для генерации и валидации | Официальные правила сообщества и справка Pinterest; содержит актуальность версии и условия проверки |
| `knowledge/pinterest-community-guidelines.md` | RAG, global; запрещённые и ограничиваемые категории Pinterest | Краткая выжимка полного официального списка правил сообщества на русском языке, с датой актуальности и разграничением запрета/ограничения |
| `policy/strategist-answer-policy.md` | system prompt/backend, не RAG | Контракт ответа из `BOOSTKLIENT_3_AI_ARCHITECTURE.md` |
| `examples/strategist-dialogue-cases.yaml` | evaluation, не RAG | Синтетические сценарии и обезличенные примеры ошибок, сообщённых владельцем; не содержат чужих или реальных бизнес-данных |
| `sources/pinterest-policy-register.md` | Только после отдельной проверки применимости и хранения | Внутреннее исследование `BOOSTKLIENT_3_PINTEREST_API.md`; Pinterest API Materials нельзя автоматически копировать или индексировать |

## Правила допуска в индекс

Документ допускается к индексации только если он имеет установленный источник, владельца, язык, scope, дату проверки и статус `approved`. Изменяемые правила и платформенные сведения должны иметь дату проверки и процедуру обновления. Записи Business, история переписки и Pinterest API Materials не входят в глобальный корпус.

Точные инструкции удаления, tenant isolation, overlap и дедупликации определены в `BOOSTKLIENT_3_AI_ARCHITECTURE.md`. Подключение документов к индексу подтверждается записями `KnowledgeDocument` и `KnowledgeChunk` в базе данных; обычный dry run этих записей не создаёт.

Реальные данные Business, Pinterest API и чата не используются для дообучения модели или общего evaluation-корпуса. Для оценки поведения применяются только синтетические примеры из `examples/`. Передача минимально необходимых данных модели для конкретного ответа — отдельный процесс и не означает дообучение; условия провайдера по обработке данных проверяются отдельно.
