## Подтверждённый дефект backend

Если модель завершала чтение сразу после страницы с bookmark, backend
показывал её ответ «Всего2», хотя данные неполные. Воспроизведено
integration-тестом с подставной моделью: до исправления тест падал.
В живом прогоне модель сама загружала следующую страницу; этот дефект
найден проверкой границы backend, а не выдан за наблюдённый ответ GigaChat.

Теперь незавершённые источники отслеживаются по аргументам без bookmark
и page_size. JSON options нормализованы; следующая завершённая страница
закрывает только тот же источник. Если источник остаётся незавершённым,
неподтверждённый ответ модели заменяется кратким `pagination-incomplete`:

> Список загружен не полностью: следующие страницы не получены. Точное общее количество неизвестно.

Этот консервативный ответ также используется после достижения лимита
6 чтений. Usage уже выполненных запросов сохраняется. Guard не проверяет
содержание записей или достоверность данных Pinterest и не выполняет
дополнительные платные запросы.

Регрессии: раннее завершение с ложным total, полные две страницы с JSON
options в разных представлениях и разным page_size, предел6 чтений.
26 targeted tests OK. Остальные сценарии повторно проверены live после
изменения, HTTP200 отдельно не считается точностью.
