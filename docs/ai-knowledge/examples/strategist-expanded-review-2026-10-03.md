## Покрытие

36 сценариев: 26 из существующего набора и 10 новых. Проверены реальные chat view, AJAX-отрисовка, изолированные диалоги, известный/пустой профиль, синтетическая история, смена темы, недоступный RAG, язык и формат, реклама/API/органика, продажи и клики, спам и CTA. Два отдельных случая требуют API-фикстуры/проверки срока источника и не засчитываются как живые проверки реального Pinterest API. Сроки источника дополнительно покрыты offline-тестами.

Последний полный прогон: 37 ответов для 36 сценариев (один диалог состоит из двух вопросов), HTTP200. В нём 16 ответов GigaChat-2-Pro, остальные из проверенных источников/проверок данных. После адресных исправлений 12 спорных случаев проверены по три раза; затем ещё три изменённых случая проверены по три раза. Это проверка перечисленных сценариев, не гарантия для произвольного разговора.

## Найдено и исправлено

- Перенос 800 символов из Review Pin specs на API без API-спецификации. Теперь граница источника указана явно.
- Выдуманные ссылки и платформенные нормы при недоступном RAG. Нормативный ответ о Pinterest без проверенного материала останавливается до LLM.
- Защита прежнего ложного совета «10 пинов — правило». Ответ исправляет утверждение с учётом предыдущего ответа модели.
- Универсальный план для бизнеса без известного товара; сначала уточняется товар/услуга.
- Ошибочное буквальное объявление обычного CTA недопустимым, отсутствие оговорки при уточнении по истории ассистента.
- Широкий запрет всех сторонних программ вместо отказа от неподтверждённого автокликера и обхода блокировки.
- Утверждения, будто коммерческий контент сам по себе является спамом.
- При проверке текста модель выдумывала выгодную цену и возможность вручную пройти «спам-фильтры Pinterest». Для запроса о спаме и уникальности проверяются фактический текст и отсутствие истории, без добавления свойств товара и гарантий модерации.
- Многословный старт нового аккаунта с известной нишей: теперь краткий практический совет, не платформенная норма.

## Примеры после исправлений

### api_length_scope

Лимиты из Review Pin specs относятся к перечисленным там форматам пинов. Этот источник не подтверждает контракт Pinterest API или лимиты всех рекламных форматов; автоматически переносить туда число 800 нельзя. Нужна спецификация конкретного метода или формата.

Источник: [Review Pin specs](https://help.pinterest.com/en/article/review-pin-specs)

### unsupported_rule_without_rag

Сейчас у меня нет доступного проверенного источника по этому правилу Pinterest. Подтвердить норму или дать подтверждающую ссылку не могу.

### unsupported_numeric_recommendation

Сейчас у меня нет доступного проверенного источника по этому правилу Pinterest. Подтвердить норму или дать подтверждающую ссылку не могу. Практический темп можно подобрать экспериментом: сравнивать сохранения и исходящие клики при посильной подготовке оригинального контента.

### corrects_previous_wrong_recommendation

Ранее названное число не подтверждено как правило. В проверенной справке Pinterest нет обязательной нормы количества пинов в день. Число «10 ежедневно» тоже не могу подтвердить как требование. Pinterest советует регулярно создавать оригинальный контент, ориентируясь на неделю. Источник: [справка Pinterest](https://help.pinterest.com/en/business/article/pin-performance-and-distribution)

### pinterest_keyword_stuffing_and_unknown_history

В тексте есть повторение близких ключевых слов — это признак возможной набивки. Уникальность для аккаунта без истории публикаций не проверена. Сделай описание естественным, используя только известные свойства товара; смешение языков само по себе не доказывает нарушение. Это оценка текста, а не одобрение модерацией.

Источник: [Правила сообщества Pinterest](https://policy.pinterest.com/ru/community-guidelines)

### profile_is_available_but_account_details_are_not

Предлагаю начать с доски по одной теме твоего бизнеса. Для первого пина возьми фото реального товара или пример услуги и добавь ссылку на соответствующую страницу. Затем оцени сохранения и исходящие клики, прежде чем расширять контент.

### organic_cta_policy_followup

Общего запрета на обычный CTA нет. Призыв должен соответствовать товару и странице по ссылке, без обмана и неподтверждённых обещаний. Это вывод из опубликованных правил, а не одобрение конкретного пина модерацией.

Источники: [справка Pinterest](https://help.pinterest.com/en/business/article/pin-performance-and-distribution), [Правила сообщества](https://policy.pinterest.com/ru/community-guidelines)

## Проверки и расходы

- 98 Django-тестов прошли; check и git diff --check без ошибок, makemigrations изменений не обнаружил.
- Новый YAML остаётся вне RAG. Критерии не передаются модели как инструкция ответа; синтетический пользовательский контекст/история помечены фикстурой.
- Все тестовые БД отдельные, настоящие бизнесы и аккаунты не читались. Копировалась только одобренная глобальная база знаний.
- Запускатель пишет каждый ответ сразу, сохраняет маршруты, шаги, время и usage, валидирует сценарии до создания тестовой БД, останавливается по уже накопленным 60000 chat tokens и не повторяет ошибочный запрос автоматически. Это не жёсткая граница счёта API.
- За пять этапов: 155 ответов, 83333 токенов по AIMessage usage. Эмбеддинги запросов и полный биллинг сюда не включены.
- Последний полный прогон: 27516 chat tokens; последний прогон12×3 и последние3×3 — 0 chat tokens, поскольку сработали проверенные пути без LLM. Нельзя называть это 45 платными ответами модели.
- Медиана времени ответа GigaChat последнего полного прогона: 2.27с; p95 не оцениваем как устойчивый показатель на 16 ответах. Денежная стоимость и объём рабочих пользовательских задач не измерены.

## Ограничения

Реальная публикация, продажи магазина и реальные подключённые аккаунты этим прогоном не проверялись. Положительный сценарий с дневным пиком из Pinterest API не заменялся пользовательским JSON и остаётся отдельной задачей интеграционной проверки. Без доступного источника мы сообщаем ограничение вместо уверенного ответа. Языковые и открытые советы остаются вероятностными; новый найденный дефект надо сохранять отдельным сценарием. Проверка не обучает веса модели. Полные локальные транскрипты — .kilo/agent-state/runtime/strategist-expanded*.json, не в Git.
