## Воспроизведённые дефекты refresh

- JSON ошибка токенного endpoint выходила как ValueError; malformed объект
  давал TypeError/KeyError, пустой access_token записывался как успешный.
- Устаревший instance без refresh_token мог ошибочно отметить живой профиль
  REAUTH_REQUIRED, хотя в БД refresh-token присутствовал.
- Устаревший instance отключённого аккаунта пытался расшифровать уже стёртый
  token и падал. Эти дефекты воспроизведены только synthetic mock-тестами.

Теперь состояние, наличие refresh и статус проверяются по строке БД
под select_for_update. DISCONNECTED/deleted аккаунт не обновляется.
Ответ endpoint проверяется до замены credentials: непустой access,
корректный положительный срок, строковые scope/refresh если присутствуют.
Неверный JSON/credentials/expiry дают безопасную PinterestOAuthError.
Временные ошибки и локальная ошибка шифра сохраняют CONNECTED и старые
credentials; постоянная OAuth ошибка требует переподключения.
Документация проверена:
https://developers.pinterest.com/docs/getting-started/set-up-authentication-and-authorization/
