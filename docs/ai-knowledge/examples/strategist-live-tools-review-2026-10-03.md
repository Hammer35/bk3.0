# Живые вызовы инструментов GigaChat — 3 октября 2026

## Метод

Настоящий authenticated AJAX chat и настроенная GigaChat-2-Pro. Каждый
сценарий в отдельной беседе уникальной временной PostgreSQL базы. Только
вымышленные бизнесы и Pinterest-профили. `read_pinterest_data` реально
проверяет account_key, бизнес, статус и scopes, но транспорт Pinterest
подменён fixtures. RAG для этих сценариев отключён. Сценарии и критерии
не передаются в prompt целиком: модель получает только вопрос и контекст.

Набор: `strategist-live-tools-cases.yaml`, версия 1, 5 сценариев. Runtime
JSON сохраняются отдельно от Git в `.kilo/agent-state/runtime/strategist-live-tools*.json`.
Final trace включает фактическую модель каждого запроса, tool calls,
выбранный профиль/ресурс и вызовы синтетического транспорта. Отказ backend
не выдаётся за ответ модели: различаются `gigachat` и `data-read/read-error`.

## Найденные ошибки и исправления

1. При двух профилях модель просила пользователя прислать `account_key`.
   Теперь prompt требует только @имя и запрещает запрашивать UUID/токен.
2. Модель передавала неверный UUID. Prompt требует копировать точный UUID
   из предоставленного контекста, а backend блокирует выбор чужого профиля.
3. Backend раньше разрешал инструменту выбрать другой CONNECTED-профиль
   того же бизнеса вместо явно указанного пользователем. Regression-тест
   сначала падал, теперь такой запрос блокируется до чтения источника.
4. Точка в конце предложения включалась в @имя и вызывала ложный отказ.
   Удаление завершающей точки из упоминания закрыто regression-тестом.

Дополнительные offline проверки запрещают подставлять известный ключ для
неизвестного @имени и выбирать один профиль при нескольких без уточнения.
Новая fixture-валидация проверена offline; обычный evaluator сохранён.

## Ограничения

Реальные Pinterest API/OAuth, все ресурсы и стабильность на всех возможных
вопросах этим набором не доказаны. Финальная выборка мала: median/p95 не
являются оценкой производственной скорости. Гарантии правильного UUID
от модели нет; backend прекращает чтение при несовпадении профиля.
Дообучение и смена модели по этим результатам не требуются.

После live-приёмки guard уточнён для сравнения нескольких явно названных
профилей: разрешены только перечисленные пользователем аккаунты. Это
покрыто отдельным offline regression, одиночные условия не изменились.
Полный итоговый suite:125 тестов OK (44,066 с), check/migrations/diffcheck
без ошибок. Все временные evaluation DB удалены (остаток0).
