# Правила совместной работы агентов · BoostKlient / курс Pinterest

Над проектом работают два агента: **Codex** (панель Codex в VS Code) и **Claude** (панель Claude Code).
Этот файл читают оба. У Claude в `CLAUDE.md` стоит ссылка `@AGENTS.md`.

У обоих агентов полный доступ к файлам. Пользователь его не ограничивает намеренно.
Значит, от порчи проекта защищает только дисциплина, описанная ниже. Её соблюдение обязательно.

## Роли

**Codex руководит и проверяет.** По новому прямому поручению пользователя 8 октября 2026 передаёт переделку всех15роликов Claude, контролирует соответствие сцен озвучке и сам просматривает итоговые MP4.

**Claude выполняет переделку.** Скрипты, захват в видимом браузере аккаунта Анны, монтаж, клипы, субтитры, комплекты площадок. Пользователь должен видеть окно браузера, реальные действия и момент захвата. Headless-захват запрещён. Новые версии отдельно; старые не перезаписывать. Никаких новых платных сервисов.

## Зоны владения

**В чужую зону можно только читать. Всегда. Без исключений.**
Нужно изменить файл в чужой зоне — пиши `ВОПРОС` в журнал и жди, либо бери замок (ниже).

## Замки на файлы

Папка `.locks/`. Один замок — один файл внутри неё. Агент создаёт и удаляет **только свои** замки,
поэтому при постановке замка мы не можем помешать друг другу.

Перед работой в общей зоне:

```bash
scripts/lock.sh list                  # посмотреть, что занято
scripts/lock.sh take <имя> claude "что делаю"
scripts/lock.sh free <имя> claude      # сразу после окончания
```

- `<имя>` — короткий слог задачи или пути, например `урок-09` или `КУРС_PINTEREST`.
- Если замок занят другим агентом — **не ждать и не снимать его**, взять другую задачу
  и записать в журнал, что было занято.
- Замок старше 6 часов считается забытым. Снять его можно, но обязательно записать это в ленту журнала.
- Замок не заменяет здравый смысл: он не защищает от двух правок, сделанных до его постановки.
  Поэтому сначала замок, потом чтение файла, потом правка.

## Журнал — канал связи

`ЖУРНАЛ.md` в корне. Единственный способ передать что-то другому агенту.
Пользователь не должен пересказывать нам слова друг друга.

- Перед началом работы агент **читает** журнал целиком.
- Журнал **только дописывается в конец ленты**. Чужие записи не редактируются и не удаляются.
  Так два агента не затрут друг друга, даже если пишут почти одновременно.
- Запись: дата, кто, что сделал или о чём спрашивает. Коротко, без воды.
- Вопрос помечается `ВОПРОС → Codex` или `ВОПРОС → Claude`. Ответ — отдельной записью.
- Раздел «Сейчас в работе» вверху правит только тот агент, чью строку он меняет.

## Порядок работы

1. Прочитать журнал.
2. Объявить задачу записью в ленту, чтобы второй агент видел, за что ты взялся.
3. Если задача трогает общую зону — взять замок.
4. Сделать коммит до начала крупной правки, чтобы откат занимал секунду.
5. Сделать работу, не выходя за свою зону.
6. Снять замок, дописать результат в ленту.

## Прямой вызов

Вызовы Claude возобновлены по прямому новому поручению пользователя. Codex передаёт конкретные задания и принимает результат по фактическим MP4.

## Что нельзя

- Коммитить прямо в `main`. Текущая ветка — `docs/pinterest-course-launch-plan`.
- Удалять или перезаписывать готовые материалы в `КУРС_PINTEREST/` без решения пользователя.
- Не трогать `.env`, ключи и учётные данные. Исключение: по прямому поручению пользователя разрешено перемещать OAuth JSON-клиент YouTube-загрузчика в `/home/evgen/bk3.0/.local_secrets/youtube_oauth_client.json` и использовать его для конкретной загрузки; каталог должен иметь права `700`, файл — `600`, путь должен быть исключён из Git. Не выводить секреты в терминал, журнал или сообщения; токен хранить только в `/home/evgen/bk3.0/.local_secrets/youtube_token.json` с правами `600`; путь исключён из Git.
- Делать `git checkout`, `git reset --hard`, `git stash` и прочее, что сносит чужую незакоммиченную работу.
- Снимать чужой свежий замок.

## Правила по содержанию курса

- Только достоверное. Ничего не выдумывать: ни цифр, ни обещаний охвата, кликов и продаж.
- Скриншоты — реальные, с живого учебного аккаунта. Интерфейс не дорисовывать.
- **Каждый новый скриншот показывать пользователю до монтажа.** Файл и SHA256 — в `Версии_скриншотов.csv`.
- Анна — вымышленная героиня курса, это оговаривается в материалах.
- Не изображать результат, который фактически не проверен в Pinterest.
- Платные сервисы и API — только после подтверждения пользователя, с предупреждением о расходах.

## Визуальный стиль креативов BOOSTKLIENT

- Все будущие креативы BOOSTKLIENT выдерживать в одобренном пользователем стиле: вертикальная редакционная иллюстрация, чёрный, белый и сигнально-красный, высокий контраст, простые формы и свободное пространство.
- Визуальный сюжет может связывать карточки товаров с контентом для Pinterest; не изображать гарантированный трафик, продажи или рост.
- Не генерировать надписи внутри иллюстраций. Текст добавлять отдельно и только после проверки формулировки.
- Не рисовать выдуманный интерфейс приложения, аналитику, цифры, деньги или официальный логотип/знак Pinterest. Для демонстрации функций использовать только реальный экран приложения и показывать его пользователю до публикации.
- Не выбирать конкретную категорию товара, если её нет в утверждённом тексте поста.

## Прямая связь между агентами

Помимо журнала агенты могут спрашивать друг друга напрямую, без пользователя:

```bash
scripts/ask_codex.sh "вопрос или поручение"    # Claude → Codex
scripts/ask_claude.sh "вопрос или поручение"   # Codex → Claude
```

- Ответ приходит в stdout. Это новая сессия соседа: контекста его панели у неё нет, всё нужное пишите в вопросе.
- По умолчанию сосед работает только на чтение (Codex: `read-only`, Claude: `plan`). Для правок: `CODEX_SANDBOX=workspace-write` или `CLAUDE_PERMISSION=acceptEdits`. Зоны владения и замки действуют и здесь.
- Итог договорённости всё равно записывать в `ЖУРНАЛ.md`.
